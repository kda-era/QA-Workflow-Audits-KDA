Module 3: Defect & Execution Error Reports

[DEF-001] Make.com Scenario Fails with BundleValidationError on Airtable Date Field Mapping

Severity: High Priority: High
Subsystem: Integration Pipeline (Make.com Webhook → Airtable API) Environment: Staging / Make.com Scenario Execution Engine
Reporter: QA Application Tester Status: OPEN (Defect Logged)

Description: Executing the service request workflow triggers a BundleValidationError on the Airtable Create/Update Record module due to an unparsed date parameter passed from the custom webhook JSON payload.

Steps to Reproduce:

  1. Submit the Softr request form with a date input selected.
  2. Trigger the HTTP payload via Custom Webhooks module to Make.com.
  3. Inspect Module #2 (Airtable Record Creation) execution details in Make.com inspector.

Expected Result: Make.com formats the raw date string into an ISO-8601 compliant date before passing to Airtable (200 OK / Record Created).

Actual Result: Airtable module throws Code: BundleValidationError with error message: "A required field is empty or in the wrong format. Validation failed for 1 parameter(s). Invalid date in parameter 'fldA0icVPxAAPPsxe'."

[Execution Trace Log - Make.com Inspector]
Module: Airtable (Create/Update Record)
Error Type: BundleValidationError
Failed Parameter: fldA0icVPxAAPPsxe (Target: Date Field)
Summary: 1 operation attempted | 1 credit used | 0 bundles generated

Figure 1.1: Make.com scenario execution inspector showing BundleValidationError on field fldA0icVPxAAPPsxe (image_c58d66.png).

QA Remediation Note: Wrap the mapped field with a formatDate() inline function inside Make.com or configure a fallback error handler route to handle unparseable dates gracefully.

[DEF-002] Make.com Scenario Throws HTTP 422 RuntimeError on Airtable 'Services Required' Field

Severity: High Priority: High
Subsystem: Data Ingestion Pipeline (Softr Form → Make.com Router → Airtable Base) Environment: Staging / Make.com Scenario Execution Engine
Reporter: QA Application Tester Status: OPEN (Defect Logged)

Description: Submitting multi-select option values from the web portal form causes an unhandled HTTP 422 error at the Airtable API mapping step due to parameter string format mismatches.

Steps to Reproduce:

  1. Log into the Softr Client Request Portal.
  2. Select multiple options under the Services Required field and click Submit.
  3. Inspect Make.com scenario execution status at Module #2.

Expected Result: Make.com parses array strings into valid Airtable option choices, successfully creating a record (HTTP 200 OK).

Actual Result: Airtable API returns an HTTP 422 error: "[422] Cannot parse value for field Services Required. Code: RuntimeError. Origin: Airtable".

[Execution Trace Log - Airtable API Module]
HTTP Status: 422 Unprocessable Entity
Error Type: RuntimeError | Origin: Airtable API Response
Details: Cannot parse value for field 'Services Required'
Summary: 1 operation attempted | 1 credit used | 0 bundles generated

Figure 2.1: Make.com inspector showing HTTP 422 RuntimeError on 'Services Required' field mapping (image_c58da3.png).

QA Remediation Note: Use the split() formula in Make.com to convert comma-separated string payloads into an explicit Array collection that Airtable accepts for multi-select fields.
